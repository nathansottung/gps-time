# GPS Time v1.4.0-rc.7

**Date:** 2026-10-05 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.6](v1.4.0-rc.6.md)

Seventh release candidate, and the bundle the two deploy checklists target. It collects the fixes reported from the first Pi build, the local-time clock, and the handling of chrony polling the station itself.

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.6 (#42 to #53).

## The installer now changes one more line of chrony.conf (#52)

- `install.sh` comments out `sourcedir /run/chrony-dhcp`, so chrony no longer takes NTP servers from DHCP. A router that names the station as the LAN's NTP server could otherwise make the station poll, and after a PPS loss follow, itself.
- Only that line changes. The file as it was is kept as `/etc/chrony/chrony.conf.before-gps-time-pi`.
- **Check before upgrading:** a station whose only network fallback came from DHCP has none afterwards. Add a `server` or `pool` line, or keep the old behavior with `sudo GTP_KEEP_DHCP_NTP=1 bash install.sh`.

## chrony polling the station itself is detected (#48)

- A chrony source that is one of the station's own addresses is marked `is_self` and shown as THIS STATION. It is never counted as a network reference or a fallback.
- If chrony selects it, the status is `HOLDOVER · NO EXTERNAL REFERENCE · CHRONY SELECTED THIS STATION ITSELF`.

## Fixes reported from the first Pi build

- **Astronomy says why it is unavailable** (#43, #51). `/api/almanac` and the legacy widget give the reason (missing, unreadable or truncated ephemeris; a failed calculation). The installer makes the code, venv and ephemeris readable by the service user and ends with a self-check as that user. The legacy Sun widget says "loading" until a request has actually failed.
- **NTP client list** (#44). The unprivileged web service can't use chronyd's control socket. A helper service running as `_chrony` publishes `chronyc -n clients` to `/run/gps-time-pi/` every 15 s. chrony's configuration isn't changed.
- **Satellite C/N₀ bars in the legacy dashboard** (#50) rendered empty because of a CSS `display` rule, not the content security policy.

## Local time (#45, #47)

- The Overview has a big clock showing the station's time in the local zone, with UTC and the Unix epoch beneath, and a 12/24-hour toggle. It says GPS/PPS only when chrony has the PPS refclock selected.
- The zone comes from an operator override, or offline from the station's position (`tzfpy`, installed into the venv). In `hidden` privacy mode it is never derived from the position.
- Display only: the system clock, chrony, logs and API timestamps stay on UTC.

## NMEA refclock offset recommendation (#49)

- While PPS is selected, the PPS diagnostics page shows the configured NMEA offset, the measured residual and a suggested offset. Report only: the operator edits `chrony.conf`.

## Not yet verified on a Pi

- The installer's DHCP step (#52), the self-source detection (#48), the local-time clock (#45, #47) and the NMEA recommendation, including chrony's sign convention on this hardware (#49).
- The cause the NTP client helper was built on (#44) is derived from chrony's design and has not been confirmed on the Pi.
- The Pi's own reason for astronomy being unavailable (#43) is not known yet; `/api/almanac` now states it.

## Known open issues

- chrony history semantics (GPS-003, GPS-007); unbounded RAM tracking log (GPS-011, GPS-012).
- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- A 32-bit Raspberry Pi OS (`armv7l`) isn't covered by the wheel check.
- Full list: `docs/STATUS.md`.

## Deploy and rollback

- New Pi: `docs/deploy/fresh-pi-install.md`. Existing v1.3 station: `docs/deploy/first-pi-deploy.md`.
- `install.sh` restarts chrony on every run, as it has since v1.3.
- Rollback: `docs/development/raspberry-pi-deploy.md` → "Rollback". To undo the DHCP change, restore `chrony.conf.before-gps-time-pi` or remove the leading `# ` from the line, then restart chrony.
