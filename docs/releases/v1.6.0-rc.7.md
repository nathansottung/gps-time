# GPS Time v1.6.0-rc.7

**Date:** 2026-11-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.6.0-rc.6](v1.6.0-rc.6.md); last stable [v1.4.0](v1.4.0.md)

rc.6 with a web SDR fix, in one PR (#177). On the owner's Pi, OpenWebRX+ couldn't open its dongle: it logged `usb_open error -3`, and the installer had printed `0 RTL-SDR device(s) in OpenWebRX+ set to serial 00000001`. Everything in rc.1 to rc.6 is still here. v1.5.0 stays skipped. **The formal soak waits for the antenna move.**

None of this changes chrony, gpsd or the PPS setup. All of it is inside the optional web SDR (`GTP_WEBSDR=1`).

## What's fixed

| What | Guide |
|---|---|
| **USB access.** `-3` is libusb's access error. The installer adds `/etc/udev/rules.d/61-gps-time-rtl-sdr.rules`, which gives RTL2832U dongles (0bda:2832, 0bda:2838) to `plugdev` with mode `0660`. The OpenWebRX+ unit is already in that group. The installer applies the rule to the dongles plugged in now (`udevadm trigger`), so no replug or reboot is needed. Before, a dongle plugged in before the package was installed could stay root-only. | `deploy/websdr.md` → "The dongle: serial and USB access" |
| **0 devices.** A `settings.json` with no RTL-SDR device (no `sdrs` key, or only other radios) left OpenWebRX+ on its built-in device, which names no serial. The installer now adds one, keeps everything else, and stops if it still can't set one. | same |
| **Exact serial.** The device is pinned as `serial=<serial>`, so `rtl_connector` never reads `00000001` as a device index. | same |
| **Dongle report.** The install lists each RTL-SDR: its port, serial, and whether `plugdev` can open it. It warns when no dongle has the web SDR's serial, or when two share it. Shared serials are common with factory `00000001` serials; the fix is `rtl_eeprom`, done by the owner and never by the installer. | same |
| **OpenWebRX+'s online lists are off.** These are the receiver-list scraping (receiverbook.de, kiwisdr.com, websdr.org), RepeaterBook (which would get the receiver's position) and EIBI. Their cache files are pinned as fresh and empty. OpenWebRX+ has no setting for this. | `deploy/websdr.md` → "Online receiver lists off" |

## What the upgrade changes on the station

Only with the web SDR installed (`GTP_WEBSDR=1`, now or before):
- **New file:** `/etc/udev/rules.d/61-gps-time-rtl-sdr.rules`. udev reloads its rules, and USB devices with vendor 0bda are re-triggered (a `change` event: their access only). readsb and dump978 are in `plugdev` too, so nothing they had is taken away.
- **`/var/lib/openwebrx/settings.json`:** each RTL-SDR device's `device` becomes `serial=<serial>`, and an RTL-SDR device is added if there was none. The old file is copied beside it as `settings.json.gps-time-prev`.
- **`/var/lib/openwebrx/receivers.json`, `repeaters.json`, `eibi.json`:** empty lists dated 2037-12-31. Any list already downloaded is dropped.
- **The `plugdev` group** is created if the system has none (Raspberry Pi OS and Debian have it).

## Deploy

From a clean working tree on Windows, in a normal PowerShell window. Set only the flags you use. Empty ones aren't passed, and the Pi keeps its saved serials and settings.

```powershell
git fetch --tags
git checkout v1.6.0-rc.7
git describe --tags --dirty          # must print exactly v1.6.0-rc.7

$env:GTP_SDR = '1'                       # SDR stack (0 removes it)
$env:GTP_SDR_1090_SERIAL = ''            # 1090 MHz dongle serial; empty keeps the saved one
$env:GTP_SDR_978_SERIAL = ''             # 978 MHz serial; empty keeps it, 'none' clears it
$env:GTP_SDR_PPS_SERIAL = ''             # PPS-marker serial; empty keeps it, 'none' clears it
$env:GTP_TAR1090 = '1'                   # live aircraft map (0 turns it off)
$env:GTP_WEBSDR = '1'                    # web SDR (0 removes it)
$env:GTP_WEBSDR_SERIAL = ''              # only if it shouldn't share the 1090 MHz dongle
$env:GTP_WEBSDR_PORT = '8073'
$env:GTP_WEBSDR_MAX_HOURS = '4'
$env:GTP_WEBSDR_AUTH = '0'               # 0 = open to the LAN; 1 = its own login
$env:GTP_WEBSDR_REMEMBER_DAYS = '30'
$env:GTP_WEBSDR_HF = 'off'               # off | direct (SMArt v5) | native (RTL-SDR Blog V4)
$env:GTP_FEEDERS = '1'                   # each feeder stays off until turned on in Administration
$env:GTP_FEEDERS_PIAWARE = '0'
$env:GTP_FEEDERS_CUSTOM = ''             # 'host:port,host:port' (up to 4)
$env:GTP_INDEPENDENT_REFS = ''           # 1 = NIST and USNO; or 'a b'; 0 removes them
$env:GTP_KEEP_DHCP_NTP = ''              # 1 = keep DHCP-supplied NTP servers
$env:GTP_CLIPS_DIR = ''                  # a drive under /mnt, /media or /srv; empty = RAM
$env:GTP_CLIPS_MAX_MB = ''
$env:GTP_SDR_NODE = ''                   # station only: the SDR node's address
$env:GTP_NODE = ''                       # second Pi only
$env:GTP_NODE_STATION = ''               # second Pi only
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

Then read the installer's dongle lines in the deploy output, and check on the Pi as in `deploy/websdr.md` → "The dongle: serial and USB access". Remove the flags afterwards (`Remove-Item env:GTP_*`) so a later deploy doesn't pass them again.

## Not yet verified on a Pi

- The udev rule and its trigger, and OpenWebRX+ opening the dongle with them. The tests check the rule, the calls and the report against a temporary sysfs tree.
- Whether the `-3` had another cause on the owner's Pi. The dongle report and the check commands in the guide show the node's group and mode either way.
- The online lists staying off with a later OpenWebRX+ version.
- Everything in [`v1.6.0-rc.6.md`](v1.6.0-rc.6.md) → "Not yet verified on a Pi" still applies.

## Rollback

Check out `v1.6.0-rc.6` and run the same deploy command. It leaves the udev rule and the pinned list files in place; both are harmless to rc.6. To undo them by hand:

```sh
sudo rm /etc/udev/rules.d/61-gps-time-rtl-sdr.rules
sudo rm /var/lib/openwebrx/{receivers,repeaters,eibi}.json
```
