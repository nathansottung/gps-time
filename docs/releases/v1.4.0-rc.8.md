# GPS Time v1.4.0-rc.8

**Date:** 2026-10-05 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.7](v1.4.0-rc.7.md)

Eighth release candidate, and the bundle the deploy checklists target. It adds the timing-metrology features of `docs/specs/SPEC-TIMING-METROLOGY.md` §1, §3, §4 and §6. It is the candidate for the soak run on the Pi before v1.4.0.

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.7 (#54 to #59).

## Where the station stands

v1.4.0-rc.6 was deployed to the Pi on 2026-10-04: chrony selected the PPS refclock, stratum 1, system clock offset about 300 ns (owner's report). The fixes found on that build are in rc.7. **Nothing merged after rc.6 has run on a Pi yet**, which includes everything below.

Upgrade checklist for that station: `docs/deploy/upgrade-1.4-station.md`.

## Stability analysis: ADEV, MDEV, TDEV (#55)

- Timing → Stability: a log–log plot with confidence bars for ADEV, and a table at 1 s, 10 s, 100 s, 1000 s and 1 day.
- Input: the fractional second of each kernel PPS timestamp, so the result describes the system clock against PPS as Linux saw it. It is not the receiver's electrical PPS and not the oscillator alone.
- History is in RAM (4 h of seconds, 14 d of minute summaries) and starts again when the web service restarts. A value needs 3 averaging times of history, 4 for MDEV and TDEV.
- The math agrees with the published NIST SP 1065 reference values.
- The timing-chain service now polls on a fixed grid 0.25 s after each second, so its read no longer drifts across the pulse.

## Time scales (#56)

- Timing → Time Scales: UTC, local time, TAI, GPS time with week and seconds of week, Unix epoch, MJD, JD, local sidereal time.
- TAI − UTC comes from tzdata's leap-second table. The panel shows the table's source and expiry, warns 60 days before expiry, and shows the next scheduled leap second if there is one.
- UT1 − UTC appears only from an IERS file the operator places on the station. The station never fetches it.

## Independent references (#57)

- Timing → References compares the station with NTP servers chrony measures but isn't using to set the clock. It reports agreement or disagreement (limit 50 ms), never a cause, and "no external references reachable" without Internet.
- Adding NIST and USNO as `noselect` servers is an installer option, **off by default**: `sudo GTP_INDEPENDENT_REFS=1 bash install.sh`.

## NTP service counters; NMEA offsets side by side (#58)

- Network & Devices shows chrony's `serverstats`: packets received and dropped, rates, and a requests-per-minute chart. chrony doesn't count replies, so "served" is shown as received − dropped.
- PPS Diagnostics shows the configured and the suggested NMEA offset side by side.

## Changes to know before upgrading

- **`chrony.conf`** (since rc.7): the installer comments out `sourcedir /run/chrony-dhcp`. A station whose only network fallback came from DHCP needs its own `server` or `pool` line afterwards, or `GTP_KEEP_DHCP_NTP=1`.
- The chrony helper service (`_chrony`) now publishes `ntpdata` and `serverstats` as well as `clients`. It still runs a fixed list of read-only reports.
- `install.sh` restarts chrony on every run, as it has since v1.3.

## Not yet verified on a Pi

- Everything in this release, and the rc.7 items listed in its notes.
- That `_chrony` can read `ntpdata` and `serverstats` over chronyd's socket.
- That tzdata on the Pi ships `leap-seconds.list` at `/usr/share/zoneinfo/`. If not, the panel says so and uses a built-in list.
- How long a full stability recalculation takes on a Pi (at most once a minute, only while the page is open).
