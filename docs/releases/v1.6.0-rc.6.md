# GPS Time v1.6.0-rc.6

**Date:** 2026-11-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.6.0-rc.5](v1.6.0-rc.5.md); last stable [v1.4.0](v1.4.0.md)

rc.5 with the owner's rc.6 list (2026-11-04), one PR each (#172 to #175). Everything in rc.1 to rc.5 is still here. v1.5.0 stays skipped. **The formal soak waits for the antenna move.**

None of these changes chrony, gpsd or the PPS setup.

## What's new

| # | What | Guide |
|---|---|---|
| #172 | **The web SDR is open to anyone on the LAN.** Start and Stop need no admin token; there is no login by default. The station still refuses a Start from another site (Origin, Host and JSON checks), and the web SDR stays LAN-only. | `deploy/websdr.md`; ADR-0009 amended |
| #173 | **Live aircraft map**, on by default with the 1090 MHz role. tar1090 (pinned commit) shows readsb's aircraft at `http://<station>/tar1090/`, linked from Aviation, and is served by the station itself (no new listener). API additions:
- `GET /api/aircraft-map` and `GET /tar1090/…`;
- `POST /api/login` and `POST /api/logout`;
- `GET /api/auth` → `session`;
- `POST /api/admin` `websdr_start`/`websdr_stop` with no token.

The reference is `api/endpoints.md`.

## What the upgrade changes on the station

- **With the SDR stack's 1090 MHz role:**
  - The install fetches tar1090 and its aircraft database by commit (needs `git` and GitHub at install time) into `/usr/local/share/gps-time-tar1090/html`.
  - `/etc/default/gps-time-sdr` gains `GTP_TAR1090=1`.
  - Nothing new runs: the web service serves the page.
- **With the web SDR:** anyone on the LAN can start and stop it from the Radio page, which also stops ADS-B tracking for up to a session's limit.
- **Admin:** the page asks you to sign in once. On the first sign-in the station writes `admin-session.key` (0600) next to the token hash. A token kept in an open tab from before is no longer used.
- **Feeders:** unchanged unless `GTP_FEEDERS_CUSTOM` lists more than one aggregator.
- **Privacy:** switching to hidden now deletes the airband NASR set, and switching from exact to rounded drops its distances. Refresh again after switching back.

## Deploy

From a clean working tree on Windows, in a normal PowerShell window. Set the flags you use (every flag `install.sh` reads is below), then deploy:

```powershell
git fetch --tags
git checkout v1.6.0-rc.6
git describe --tags --dirty          # must print exactly v1.6.0-rc.6

# ── SDR stack: one RTL-SDR per role, by serial (deploy/sdr-stack.md) ──
$env:GTP_SDR = '1'                       # install or update the SDR stack (0 removes it)
$env:GTP_SDR_1090_SERIAL = ''            # the 1090 MHz dongle's serial (readsb, the map); empty keeps the saved one
$env:GTP_SDR_978_SERIAL = ''             # the 978 MHz dongle's serial; empty keeps it, 'none' clears it
$env:GTP_SDR_PPS_SERIAL = ''             # the PPS-marker dongle's serial (rtl_tcp); empty keeps it, 'none' clears it
$env:GTP_TAR1090 = '1'                   # the live aircraft map (default 1; 0 turns it off)

# ── Web SDR (deploy/websdr.md) ──
$env:GTP_WEBSDR = '1'                    # install or update the web SDR (0 removes it)
$env:GTP_WEBSDR_SERIAL = ''              # only if it shouldn't share the 1090 MHz dongle
$env:GTP_WEBSDR_PORT = '8073'            # its LAN port (1024-65535, not 8074)
$env:GTP_WEBSDR_MAX_HOURS = '4'          # a session ends by itself after this many hours (1-24)
$env:GTP_WEBSDR_AUTH = '0'               # 0: open to the LAN (rc.6 default); 1: its own login
$env:GTP_WEBSDR_REMEMBER_DAYS = '30'     # with the login on: "Remember this browser" days (1-365)
$env:GTP_WEBSDR_HF = 'off'               # off | direct (NESDR SMArt v5, Q branch) | native (RTL-SDR Blog V4)

# ── Feeders (deploy/feeders.md); each stays off until turned on in Administration ──
$env:GTP_FEEDERS = '1'                   # feeder support (0 removes the units)
$env:GTP_FEEDERS_PIAWARE = '0'           # 1: also FlightAware's PiAware
$env:GTP_FEEDERS_CUSTOM = ''             # your own aggregators: 'host:port,host:port' (up to 4)

# ── Timing extras (chrony steps; deploy guide) ──
$env:GTP_INDEPENDENT_REFS = ''           # 1: NIST and USNO as unselected references; or 'a b' your own; 0 removes
$env:GTP_KEEP_DHCP_NTP = ''              # 1: leave DHCP-supplied NTP servers in chrony

# ── Clips (deploy/clips.md) ──
$env:GTP_CLIPS_DIR = ''                  # a drive under /mnt, /media or /srv; empty: a capped RAM folder
$env:GTP_CLIPS_MAX_MB = ''               # the cap, in MB

# ── SDR node (deploy/sdr-node.md) ──
$env:GTP_SDR_NODE = ''                   # on the station: the node's address (or 'none')
$env:GTP_NODE = ''                       # on a second Pi only: 1 makes it a node
$env:GTP_NODE_STATION = ''               # on a second Pi only: the station's address

powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

Empty flags are not passed. The serials and settings are kept on the Pi (`/etc/default/gps-time-sdr`, `-websdr`, …), so a later deploy can leave them unset. Clear them afterwards with `Remove-Item env:GTP_* -ErrorAction SilentlyContinue`.

## Rollback

Check out `v1.6.0-rc.5` and run the same deploy command.
- **Admin:** rc.5 asks for the token on the page again, and ignores `admin-session.key`.
- **The map:** the tar1090 page stays in `/usr/local/share/gps-time-tar1090` unused; remove it with `GTP_TAR1090=0` before rolling back.
- **Feeders:** a second custom aggregator is ignored by rc.5's installer but stays installed. `GTP_FEEDERS=0` removes them all.
