# GPS Time v1.4.0-rc.1

**Date:** 2026-10-02 · **Type:** pre-release (release candidate) · **Previous baseline:** v1.3.0 (historical deployment, untagged; see `deployment-runbook.md`)

This is the first tagged version. It gives deploys a named rollback target. It is **not** a stable release. Pre-release blockers are still open (see "Known open issues"). Not yet verified on a Pi.

Source: `docs/provenance/change-log.md`, entries 2026-09-18 to 2026-10-02 (PRs #1–#18).

## Timing chain and PPS

- Backend for the PPS timing chain (`specs/CHG-PPS-HEALTH-DIAGNOSTICS.md`):
  - kernel PPS observation from sysfs;
  - pure `chronyc -n` parsers, with refclocks identified from `chrony.conf`;
  - independent stages and a PPS state machine;
  - evidence-based classification, which never names a cause;
  - one `PPS_OUTAGE` event per outage, checkpointed;
  - endpoints `/api/timing-chain` and `/api/diagnostics`.
- The status banner shows GPS/PPS Stratum 1 only when chrony selects PPS (GPS-005, GPS-006).
- Boot rule: `ACQUIRING · PPS NOT YET SELECTED SINCE BOOT` instead of a false outage. An outage opens, backdated to boot, if PPS is not selected within 30 min.
- No change to chrony, gpsd or PPS configuration.

## GNSS survey and persistence

- GNSS sampling runs in a background collector. Survey samples need a fresh, strictly newer receiver epoch (GPS-001).
- Config/survey persistence:
  - flushed on SIGTERM;
  - written atomically with fsync;
  - `config.json.prev` checkpoint;
  - corrupt files are set aside, never overwritten (GPS-013).
- logsync units run their scripts through `/bin/bash`. The installer and bundle set file modes (GPS-010).

## Location privacy

- Almanac, object lookup and sidereal time honor the privacy mode (GPS-015).
- Hidden mode also drops satellite azimuth and elevation. Satellite IDs, constellation, C/N₀ and used flags are kept.
- Docs and the demo use the US Naval Observatory example location only (GPS-024).

## Web UI (`/app/`)

- React app served by the station at `/app/`, with a typed API client and a demo adapter. A failed live request never falls back to demo data.
- Source-aware banner, timing-chain card, and a PPS Diagnostics page with COPY/DOWNLOAD.
- Fonts are self-hosted (weights 300–600). There are no runtime CDN or analytics requests.
- Vitest unit tests (26) run in CI.

## Repository

- Desktop demo for Windows and Linux; bundle builder and deploy helpers.
- `docs/STATUS.md` status table, `CLAUDE.md` project rules and the new-machine guide.
- Dependabot runs weekly for pip, pnpm and GitHub Actions. skyfield is pinned in `requirements.txt` (#17).
- Workflow actions are pinned to commit SHAs, with a CI guard (#18).

## Known open issues

- **Administrative security (GPS-014, GPS-017, GPS-019): not in this release.** The service runs as root. Admin GET routes are unauthenticated, and there is no Host/Origin check. Run it only on a trusted LAN.
- chrony history semantics (GPS-003, GPS-007), and the unbounded RAM tracking log (GPS-011, GPS-012).
- `web/dist` isn't shipped in the Pi bundle yet. On a Pi, `/app/` returns 503 unless the UI is built there.
- The ephemeris download is trust-on-first-use (GPS-020, partial).
- Full list: `docs/STATUS.md`.

## Rollback to this version

```sh
git fetch --tags
git checkout v1.4.0-rc.1
python tools/build_bundles.py
```

Then deploy the bundle with `scripts/deploy-to-pi.ps1` or `scripts/deploy-to-pi.sh`, as described in `docs/development/raspberry-pi-deploy.md`.
