# GPS Time v1.4.0-rc.2

**Date:** 2026-10-02 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.1](v1.4.0-rc.1.md)

Second release candidate. It adds administrative security and moves the installer to a venv. The changes to the service and the installer are **not yet verified on a Pi**. Keep the v1.4.0-rc.1 bundle as the rollback target (see "Rollback").

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.1 (#23–#28).

## Administrative security (#24): GPS-014, GPS-017, GPS-019

- **Every request:** a `Host` allowlist, which blocks DNS rebinding.
- **State changes** (`/api/admin`, `/api/setting`, `/api/dashboard`, `/api/dashboard/reset`):
  - POST and `application/json` only;
  - same-origin, or listed in `GTP_ALLOWED_ORIGINS`;
  - `Authorization: Bearer <admin token>` required.
- **Admin token:**
  - 32 random bytes; only its SHA-256 is stored;
  - created on first install and shown on the terminal only;
  - rotate it with `python3 -m gps_time_pi.admin_token`;
  - failed attempts are logged without the token, with per-IP backoff.
- **Unprivileged service:**
  - runs as `gps-time` with `CAP_NET_BIND_SERVICE` only;
  - `ProtectSystem=strict`, `ProtectClock=yes`, `NoNewPrivileges`;
  - admin actions go through a narrow polkit rule.
- **Demo mode** simulates admin actions. Legacy pages show a SAMPLE DATA banner.
- **Security headers and CSP.** Legacy pages allow only their own inline scripts, by hash. The web build inlines no assets.
- `/api` → `clients` is `null` (UNKNOWN) when `chronyc clients` fails, instead of an ambiguous `[]`.

## Installer (#25)

- Python dependencies are installed into `/opt/gps-time-pi/venv` instead of `pip3 install --break-system-packages` (Bookworm, PEP 668). The service runs the venv's Python.
- `apt-get update` runs before package installs.

## Version reporting (#23, #26)

- `/api` → `versions.app` and the web UI footer report the version from the git tag, e.g. `1.4.0-rc.2`, or `1.4.0-rc.2-3-gabc1234` for later commits.
- Deploy bundles carry `gps_time_pi/VERSION`. Demo mode reports the real version.
- CI checks out tags and fails if the version would be `unknown`.

## Repository

- GitHub Actions updated by Dependabot: checkout v7.0.1, setup-python v7.0.0 and setup-node v7.0.0, still SHA-pinned (#19, #20, #21).
- `web.yml` was fixed: an unquoted step name made GitHub reject the workflow.
- `web/AGENTS.md` lists `version.ts` and `auth.ts` (#27).

No change to chrony, gpsd or PPS configuration.

## Upgrade notes

- Run the deploy **interactively** (a terminal) on the first upgrade, so `install.sh` can show the admin token. Without a terminal, admin stays disabled until you create a token on the station. The command is in `docs/development/raspberry-pi-deploy.md`.
- Settings changes and admin actions in both UIs now ask for the token.
- If a hostname other than the station's own name or IP is used to reach it, add it to `GTP_ALLOWED_HOSTS` in the unit.
- Check after upgrading:
  - `systemctl status gps-time-pi`;
  - system diagnostics, NTP clients and PPS values still appear (they depend on the `_chrony` and `video` groups).

## Known open issues

- Not verified on a Pi: systemd hardening, the polkit rule, `_chrony` socket access, `vcgencmd` under `video`, and the venv install.
- chrony history semantics (GPS-003, GPS-007); unbounded RAM tracking log (GPS-011, GPS-012).
- `web/dist` isn't shipped in the Pi bundle yet.
- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- Full list: `docs/STATUS.md`.

## Rollback

- **Level 1, root service with this code:** the drop-in in `docs/development/raspberry-pi-deploy.md` → "Rollback".
- **Level 2, previous release:**

```sh
git fetch --tags
git checkout v1.4.0-rc.1
python tools/build_bundles.py
```

Deploy that bundle, then remove the polkit rule as described in the deploy guide. v1.4.0-rc.1 uses the system-wide skyfield, which `install.sh` re-installs.
