# GPS Time v1.6.0-rc.2

**Date:** 2026-11-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.6.0-rc.1](v1.6.0-rc.1.md) (could not be installed); last stable [v1.4.0](v1.4.0.md)

rc.1 with one fix: **its Pi bundle had no `modules/`**, so `install.sh` stopped at `cp -r modules` (#155). Everything else is as in rc.1: what's in it, what the upgrade changes, what isn't verified and the known issues are in [`v1.6.0-rc.1.md`](v1.6.0-rc.1.md). v1.5.0 stays skipped, and **the formal soak waits for the antenna move** (owner, 2026-11-04): the first run of this candidate is for sector data and web SDR testing.

## What was wrong, and what changed

- **`tools/build_bundles.py`** listed what goes into the Pi bundle (`PI_TOP`), and `modules` wasn't on it. Since #146, `install.sh` installs the bundled modules (all off). ADR-0007 still said the bundle ships none, and two tests checked that string, so CI never noticed.
- **Now** the bundle ships `modules/`. ADR-0007 is amended, and the two tests check the opposite.
- **New test: `tests/test_bundle_install.py`.**
  - It builds the bundle, extracts it, and runs the bundle's own `install.sh` to the end.
  - The station's destinations point into a temporary root; system commands are stubs.
  - It checks that every bundled module, the code, the UI and the units are installed, that `chrony.conf` got only the installer's edits, and that the service restart comes last.
  - It refuses any absolute path in `install.sh` that it doesn't know, so it can't write outside its root.
  - With `modules` taken out of the bundle again, it fails with the deploy's own error, `cp: cannot stat 'modules'`.
- **No change** to `install.sh`, the station code, chrony, gpsd or the PPS setup.

## Deploy

From a clean working tree on Windows, in a normal PowerShell window:

```powershell
git fetch --tags
git checkout v1.6.0-rc.2
git describe --tags --dirty          # must print exactly v1.6.0-rc.2
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

From Linux or macOS: `bash scripts/deploy-to-pi.sh <pi-host> <pi-user>` after the same checkout.

- **This is the first run of the 1.6 line on the station.** `install.sh` restarts chrony: PPS selection takes about a minute to come back, and the station records it as the installer's event. While chrony follows a network source, the clock can drift a few milliseconds, as on every upgrade.
- **Then the web service restarts** on the new code.
- **Optional, for this run** (not the formal soak): the web SDR. On the Pi, in the bundle the deploy unpacked (`~/gps-time-deploy/gps-time`): `sudo GTP_WEBSDR=1 bash install.sh`, then set its password (`docs/deploy/websdr.md`).

## Rollback

As in rc.1: check out `v1.5.0-rc.1` (or `v1.4.0`) and run the same deploy command. With `GTP_WEBSDR=1`, run `sudo GTP_WEBSDR=0 bash install.sh` from the rc.2 bundle first. Don't roll back to rc.1: it can't be installed.
