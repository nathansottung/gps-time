# GPS Time v1.5.0-rc.1

**Date:** 2026-10-26 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0](v1.4.0.md)

First release candidate of 1.5.
- **The legacy pages are gone:** `/` and their old paths redirect to `/app/`.
- **Optional modules:** off by default, each in its own sandboxed process, with a switch on Administration.
- **Station key:** observation files can be signed.
- **Validation tools:** the second pulse, and the PPS comparison tool.

None of it has run on a Pi yet. v1.5.0 follows only after a soak run, as v1.4.0 did.

Source: `docs/provenance/change-log.md`, entries after v1.4.0 (#96 to #128).

## Deploy

From a clean working tree on Windows, in a normal PowerShell window (the admin token is shown on the terminal only if the installer makes a new one):

```powershell
git fetch --tags
git checkout v1.5.0-rc.1
git describe --tags --dirty          # must print exactly v1.5.0-rc.1
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

From Linux or macOS: `bash scripts/deploy-to-pi.sh <pi-host> <pi-user>` after the same checkout.

- **Station on v1.4.0 or a 1.4 release candidate:** follow `docs/deploy/upgrade-1.4-station.md`, with `v1.5.0-rc.1` where it says `v1.4.0-rc.11`.
- **New Pi:** `docs/deploy/fresh-pi-install.md`, with the same substitution.
- **Before upgrading a station in an incident:** run `scripts/capture-pps-evidence.sh` first (#105).

## What the upgrade changes on the station

- **`/` and the old page paths** (`/admin`, `/almanac`, `/history`, `/configure`, `/zones`, `/legacy`) redirect to `/app/`. The legacy pages and the code only they used are removed (#99). Old bookmarks still land on the web UI.
- **New system user `gps-time-mod`** and **`gps-time-modules.service`**, installed **but not enabled** (#120). No module runs until the owner enables the service, turns on Experimental modules on Administration, and enables a module (#125). The Pi bundle ships no modules.
- **Station key:** created once at install, `/opt/gps-time-pi/station-key`, mode 0600, owned by gps-time (#121). Never overwritten by a later install. Back it up with the config if signed files matter to you.
- **New dependency:** `cryptography` in the station venv (#121). The installer downloads its wheel (PyPI or piwheels).
- **New tool:** `python -m gps_time_pi.secpulse`, which runs only when started (#126). Nothing about chrony, gpsd or PPS changes.

## New since v1.4.0

**Station and web UI**
- Legacy removal steps 7–9 (#99): the front door is `/app/`; ADR-0004 updated.
- Administration → Experimental modules (#125): a switch behind the admin token. Each module stays off until it is turned on by itself. The state shows UNKNOWN unless the module supervisor reports.
- PPS evidence capture script, to run before rebooting during a timing incident (#105).

**Modules and data** (SPEC-EXTENSIBILITY; ADR-0007)
- The module kit, loader and scaffolder (#117), and isolation: each module in its own unprivileged process, with resource caps and a permission guard (#120).
- The first module, `sdr-pps-marker` (research, synthetic data only) (#115, #116).
- Observation files (SigMF + `gpstime:`): writer, reader, validator (#118, #119); converters to WAV and miniSEED 2 (#122); signed with the station key and verified (#121).

**Validation and tools**
- `tools/soak_check.py`, the read-only pre-release check (#96).
- The second pulse and `tools/pps_compare.py` (#126); guide `docs/validation/second-pulse.md`.

**Optional coordinator tier**
- Coordinator skeleton for TrueNAS SCALE (#127, ADR-0008). Not part of the station, and nothing on a station sends to it.

**Docs**
- Public release preparation (#100); sky data provenance (#101, #102); README for first-time visitors (#104, #108, #109, #112).
- Specs and roadmaps (#98, #103, #106, #107, #110, #111, #113, #114).
- Bench kit, second-station guide, and the write-up of the 2026-10-17 outages (#127).

## Not yet verified on a Pi

Everything above. In particular:
- the redirects from `/`;
- the installer's new user, unit and station key on an upgrade;
- `cryptography` installing from a wheel on the Pi (CI checks that aarch64 wheels exist);
- the second pulse on real GPIO.

## Known open issues

- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- Modules: one user shared by all modules (not one per module); module output isn't shown in the web UI yet.
- Weak GNSS signal at the development station (best C/N₀ about 25 dB-Hz): an antenna and site limit, owner, 2026-10-19. A soak run can fail on outages for that reason alone.
- Full list: `docs/STATUS.md`.

## Rollback

Check out `v1.4.0` and run the same deploy command. What stays behind and is ignored by v1.4.0:
- the `gps-time-mod` user;
- the disabled `gps-time-modules.service`;
- the station key;
- the `modules_*` settings in `config.json`.

The legacy pages come back with v1.4.0. For chrony configuration and the root service: `docs/deploy/upgrade-1.4-station.md` → "Rollback".
