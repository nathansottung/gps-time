# GPS Time v1.6.0-rc.1

> **Can't be installed: use [v1.6.0-rc.2](v1.6.0-rc.2.md).** This candidate's Pi bundle has no `modules/`, so `install.sh` stops at `cp -r modules` (#155).

**Date:** 2026-11-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.5.0-rc.1](v1.5.0-rc.1.md) (pre-release); last stable [v1.4.0](v1.4.0.md)

First release candidate of 1.6. **There is no v1.5.0:** it is skipped (owner, 2026-11-04). v1.6.0 will be the next stable release, and it carries everything since v1.4.0, including all of v1.5.0-rc.1.

## The soak finding behind it

- **v1.5.0-rc.1's soak run was not clean** (check 2026-10-29, #149): four PPS outages (8,596 s in all) and 8,906 missed pulses. Every other criterion passed, and chrony kept GPS as its reference through all four.
- **The owner's decision, 2026-11-04:** skip v1.5.0 and cut v1.6.0-rc.1 from `main`. The outages are taken as a limit of this development unit's antenna and site (the owner's assessment, as on 2026-10-19). The station itself doesn't establish that: its classifications are `inferred` boundaries, never a cause.
- **Read-only checks since** (`../development/raspberry-pi-deploy.md` → "Soak run of v1.5.0-rc.1"):
  - **No RTL-SDR during the run.** The dongle's only USB connect is 2026-11-04 14:56 UTC, six days after the check (#153).
  - **Outage timing, 2026-10-04 to 2026-11-04:** 9 real outages, on 5 evenings. The three times the receiver's solution fell to 0 satellites (Oct 19, 26, 27) came at the same sidereal time, GMST 21:28–21:29. Their UTC times spread over 31 minutes. Time of day fits nearly as well (8 of 9 starts between 19:03 and 20:02 UTC). SoC temperature fits poorly. C/N₀ by sky sector wasn't recorded then. This is a lead from three points, found after looking; it names no cause.
- **The formal soak waits for the antenna move** (owner, 2026-11-04). The first run of this candidate collects C/N₀ by sky sector and tests the web SDR; it isn't checked against the soak criteria.
- **The criteria are unchanged.** v1.6.0 still needs a clean 72-hour run (`README.md` → "The soak rule"), and outage detection is not weakened. On this unit, a run can fail on outages alone.

**What's in it:**
- **The UI work planned as v1.5.1** (`v1.5.1-plan.md`), which v1.6.0 replaces:
  - the responsive layout, design pass and chart scale toggle;
  - the holdover projection;
  - module output on Administration;
  - the desktop UI review.
- **The SDR stack:**
  - an optional installer flag, `GTP_SDR=1`: rtl_tcp, readsb (1090 MHz) and dump978 (978 MHz), loopback only;
  - the SDR modules turned on and set from Administration;
  - the SDR load in the soak record.
- **The learned sky-obstruction map** (addendum §10–11):
  - C/N₀ by azimuth and elevation over days, in a capped grid on the SD card;
  - a polar heatmap on GNSS & Site;
  - satellite losses in normally blocked directions marked as expected;
  - the station's capability record, with an opt-in sky-quality summary.

None of it has run on a Pi yet. v1.6.0 follows only after a clean soak run.

- **The optional web SDR** (`GTP_WEBSDR=1`, #152): OpenWebRX+ behind a password gate, LAN only, sharing the 1090 MHz dongle (readsb stops while it runs). It logs CPU, temperature and PPS jitter while in use, and is started and stopped from Radio & SDR.
- **PPS timestamps in integer nanoseconds** end to end (#153). Before, a float of the whole timestamp stepped in about 238 ns.

Source: `docs/provenance/change-log.md`, entries after v1.5.0-rc.1 (#129 to #153).

## Deploy

From a clean working tree on Windows, in a normal PowerShell window:

```powershell
git fetch --tags
git checkout v1.6.0-rc.1
git describe --tags --dirty          # must print exactly v1.6.0-rc.1
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

From Linux or macOS: `bash scripts/deploy-to-pi.sh <pi-host> <pi-user>` after the same checkout.

- **Upgrade:** a station on v1.5.0-rc.1 (or v1.4.0) upgrades with the command above.
- **New Pi:** `docs/deploy/fresh-pi-install.md`, with `v1.6.0-rc.1`.
- **The SDR stack is not installed by this command.** It is opt-in. On the Pi, in the bundle the deploy unpacked (`~/gps-time-deploy/gps-time`):

  ```sh
  sudo GTP_SDR=1 GTP_SDR_1090_SERIAL=... bash install.sh
  ```

  Guide: `docs/deploy/sdr-stack.md`. The web SDR is opt-in the same way: `sudo GTP_WEBSDR=1 bash install.sh`, then set its password (`docs/deploy/websdr.md`). **The first run of this candidate is not the soak** (owner, 2026-11-04): it is for sector data and web SDR testing, so the web SDR may be installed. **The formal soak waits for the antenna move.** It starts at a deploy after that, without either option, for a baseline; they can be added in a later run, whose record shows their load.

## What the upgrade changes on the station

- **Modules:**
  - **Installed in `/opt/gps-time-pi/modules`:** `install.sh` now copies the bundled modules there, read only (#146). All are off; Administration lists them.
  - **No module runs** unless the owner turns on the experimental switch and a module, and `gps-time-modules.service` runs. The service is still installed but not enabled without `GTP_SDR=1`.
- **New routes:**
  - `GET /api/sdr` (read only, #146);
  - `GET` and `POST /api/oscillator/profile` (export; import with the admin token, #135);
  - `POST /api/setting {"module", "config"}` (a module's settings, admin token, #146);
  - `GET /api/sky-obstruction` and `GET /api/capability` (read only, #148);
  - `POST /api/setting {"sky_quality_share"}` (the opt-in, admin token, off by default, #148);
  - `GET /api/websdr` (read only, #152), and the admin actions `websdr_start` and `websdr_stop` (#152).
- **The polkit rule** allows the web service to start and stop `gps-time-websdr.service` too (#152). Without `GTP_WEBSDR=1` that unit doesn't exist, and the actions fail.
- **A new file on the SD card with the web SDR only:** `websdr-sessions.jsonl`, one line per web SDR session (#152).
- **A new file on the SD card:** `sky-obstruction.json` next to `config.json`. It is about 25 KB at most, written once an hour and at a clean stop, and holds no position (#148). In hidden privacy mode nothing is collected.
- **Oscillator profile imports:** an import writes `oscillator-profile.json` or `oscillator-profile-reference.json` next to the oscillator log, once per import (#135).
- **Unchanged:** `requirements.txt`, `gps-time-pi.service`, chrony, gpsd and the PPS setup. No new user, unit or dependency without `GTP_SDR=1` or `GTP_WEBSDR=1`.
- **With `GTP_WEBSDR=1`** (opt-in, #152): the OpenWebRX+ apt repository (signing key pinned by fingerprint) and the `openwebrx` package, its own unit masked; two units, never enabled at boot.
- **With `GTP_SDR=1`** (opt-in, #145): the packages `rtl-sdr`, `readsb` and `soapysdr-module-rtlsdr`, and dump978 built from a pinned commit. Four units, each on 127.0.0.1 or with no network. A localhost drop-in for the module service. The module supervisor is enabled. readsb's own unit is masked.

## Not yet verified on a Pi

Everything above. In particular:
- the UI at phone width on a real phone, with live data;
- the modules folder and the Administration settings on a station;
- `/api/sdr` reading the station's cgroups and sysfs;
- with `GTP_SDR=1`:
  - the apt installs and the dump978 build on Debian 13;
  - the units under systemd;
  - three RTL-SDRs on one USB bus;
  - their effect on PPS timing, which is what the soak record is for;
- the sky-obstruction map's classes on a real antenna. Its thresholds come from synthetic tests, and it needs 2 days of data before it says "learned";
- with `GTP_WEBSDR=1`: the OpenWebRX+ package on trixie arm64, OpenWebRX+ under its unit's hardening, the readsb handoff and the session limit (`docs/deploy/websdr.md` → "Not verified").

## Known open issues

- **Night theme:** green and cyan values are hard to read in the red night theme (#144; a design decision for the owner).
- **Concurrent connections:** the station's HTTP server keeps Python's listen queue of 5. Several browsers loading at once can be refused (#144; GPS-018).
- **Modules:** one user is shared by all modules. `sdr-pps-marker` needs the PPS injection build and bench calibration before its markers mean anything.
- **Development station:** its weak GNSS signal is an antenna and site limit (owner, 2026-10-19, and again 2026-11-04). A soak run can fail on outages for that reason alone. Its outages so far fall in the early evening UTC (above).
- **RTL-SDR on the station:** the DVB-T driver holds the dongle plugged in on 2026-11-04 until `GTP_SDR=1` or `GTP_WEBSDR=1` unloads it. With the web SDR alone, whether it comes back after a reboot isn't checked.
- **Full list:** `docs/STATUS.md`.

## Rollback

Check out `v1.5.0-rc.1` (or `v1.4.0`, the last stable release) and run the same deploy command.

**What stays behind, and v1.5.0-rc.1 ignores it:**
- `/opt/gps-time-pi/modules`;
- `module_config` in `config.json`;
- an imported oscillator profile file;
- `sky-obstruction.json` and `sky_quality_share` in `config.json`.

**With `GTP_WEBSDR=1`:** run `sudo GTP_WEBSDR=0 bash install.sh` from the v1.6.0-rc.1 bundle first (`docs/deploy/websdr.md` → "Remove").

**With `GTP_SDR=1`:** run `sudo GTP_SDR=0 bash install.sh` from the v1.6.0-rc.1 bundle first. It removes the SDR units and the drop-in. The packages and the build are kept: `docs/deploy/sdr-stack.md` → "Remove".
