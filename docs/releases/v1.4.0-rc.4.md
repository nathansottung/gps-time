# GPS Time v1.4.0-rc.4

**Date:** 2026-10-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.3](v1.4.0-rc.3.md)

Fourth release candidate, and the bundle the two deploy checklists target. The station now gets the new web UI with the bundle. **Nothing in the 1.4 line has run on a Pi yet.**

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.3 (#34–#37).

## The Pi bundle ships the web UI (#35)

- The Pi archive carries the built UI, and `install.sh` installs it to `/opt/gps-time-pi/web/dist`. `/app/` works on a station without Node. In rc.3 and earlier a station returned 503 there.
- The deploy scripts build the UI before the bundle. The deploying machine needs Node 22 with corepack.
- `tools/build_bundles.py` refuses an unbuilt UI, or one built from another version than the checkout. `--without-web` builds a bundle with no UI.

## Installer preflight (#36)

- `install.sh` stops before changing anything if it isn't run as root, chrony isn't installed, or the `_chrony` or `video` group is missing. It warns if gpsd is missing.
- It still doesn't install or configure chrony, gpsd or PPS.

## Deploy checklists (#34, #36)

- `docs/deploy/fresh-pi-install.md`: a newly flashed Raspberry Pi OS Lite.
- `docs/deploy/first-pi-deploy.md`: upgrading a v1.3 station, with backups and rollback.

## What `install.sh` does to timing on every run

Unchanged since v1.3:

- It makes sure `/etc/chrony/chrony.conf` has `log tracking` and `logdir /run/chrony-log`.
- It **restarts chrony**. Expect a few minutes before chrony selects PPS again.

## Known open issues

- Not verified on a Pi: systemd hardening, the polkit rule (needs polkit ≥ 121), `_chrony` socket access, `vcgencmd` under `video`, the venv install, the deploy scripts, the web UI install.
- Python 3.13 (Raspberry Pi OS on Debian 13) isn't covered by CI, which runs 3.11.
- chrony history semantics (GPS-003, GPS-007); unbounded RAM tracking log (GPS-011, GPS-012).
- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- Full list: `docs/STATUS.md`.

## Upgrade notes and rollback

- Deploy from an interactive terminal so the admin token is shown; keep the token. Add extra hostnames to `GTP_ALLOWED_HOSTS`.
- Rollback: `docs/development/raspberry-pi-deploy.md` → "Rollback", and section 6 of `docs/deploy/first-pi-deploy.md` for a v1.3 station.
