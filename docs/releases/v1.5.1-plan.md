# GPS Time v1.5.1: plan

**Status:** PLAN (owner, 2026-10-26: "Plan v1.5.1 (UI work) to follow the v1.5.0 soak"). Nothing is tagged or deployed. Release mechanics: `README.md` in this folder.

## Why a 1.5.1

**Not in v1.5.0:** the stable v1.5.0 tag goes on the soaked candidate's commit (`709145f`, v1.5.0-rc.1), not on a later `main`. So the UI work merged after rc.1 isn't in v1.5.0:
- the responsive layout;
- the design pass;
- the linear/log chart toggle;
- the holdover panel.

**What v1.5.1 is:** the release that carries it to the station. It is a **UI release**: no change to timing behaviour (chrony, gpsd, PPS) and nothing that touches the soak criteria's code paths beyond what is already on `main`.

## Before rc.1 (proposed; one PR each)

1. *Done in [#142](https://github.com/nathansottung/gps-time/pull/142).* **Module output in the web UI.** This closes the v1.5.0 known issue "module output isn't shown in the web UI yet" and the PPSM "Health" row.
   - **Source of the data:** the supervisor already keeps each module's latest 20 items in RAM and publishes them in `/run/gps-time-modules/status.json`.
   - **API:** `/api/modules` adds each enabled module's latest observation and result.
   - **Page:** Administration → Experimental modules shows them as labeled values, with provenance and age.
   - **Limits:** read-only, no new process; the web service still never loads modules.
   - **Privacy:** module values are already privacy-filtered at the source. A test checks that nothing with a station position passes through.
2. **A flaky test.** `tests/test_pps_evidence_capture.py` matched a wall-clock timestamp (`…:38.92…`) against the example position's digits, which failed one CI run of #140. The fix: strip timestamps before the position check.
3. **A desktop UI review of the candidate.** Use the demo (`scripts/run-demo.ps1`) at 360, 768, 1280 and 1920 px, in both themes and screenshot mode. Any bug found is fixed before the notes PR. No new features at this step.

**Version number:** v1.5.1 is the owner's name for it. It adds API routes (oscillator profile export and import) besides the UI. If a minor version is preferred for new routes, the same plan applies as v1.6.0.

## Checks on the Pi after the owner deploys rc.1

Seen in the demo and in browser tests only so far. On the station:

- **Layout:** every page at phone width and at half-screen. The drawer navigation, and no horizontal scroll (#129).
- **Contrast and states:** in the dark and red night themes. The loading mark `…` before the first answer, and "the station did not answer" after a failure (#130).
- **Charts:** the log/linear toggle on the Overview Δt, offset history, holdover and stability charts, with the station's real data (#131).
- **Holdover panel:** with the station's own oscillator log. The temperature range comes from the last 24 h of bins. Expect "not enough data" if the log is short (#135).
- **Profile file:** export downloads a file with the board's serial hash and no position. Re-importing it on the same board reports `match`.
- **Experimental modules:** with the module service off, it shows UNKNOWN, unchanged from v1.5.0.
- **Soak criteria:** they still pass, especially the `/api/ping` round trip while pages load. The design pass and the holdover computation run in the browser and on request.
