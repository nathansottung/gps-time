## What 1.4 contains, relative to v1.3.0

### Timing chain and PPS

- The GNSS → PPS → chrony chain as independent stages with a PPS state machine. Refclocks are identified from `chrony.conf`; every chronyc call uses `-n`.
- The banner says GPS/PPS Stratum 1 only when chrony selects PPS. A boot rule shows ACQUIRING instead of a false outage.
- One `PPS_OUTAGE` event per outage, checkpointed, with an evidence-based classification that names a boundary in the signal path, never a cause.
- Outage evidence on the SD card: one file per outage (the event, a 10 s timeline, chrony lines ±5 min), 20 MiB cap, no position.
- PPS read on its own thread; missed pulses (the kernel never counted them) told apart from unread ones.
- chrony polling the station itself is detected and never counted as a reference; the installer stops chrony taking NTP servers from DHCP.
- chrony history semantics fixed (GPS-003, GPS-007): the tracking log read by named column; "remaining correction" instead of "error"; chronyc's max-error bound.
- chrony's tracking log flushed append-only, with caps on the RAM log (8 MiB) and the SD copy (16 MiB).

### Timing metrology

- Stability analysis: ADEV, MDEV and TDEV from kernel PPS timestamps, with confidence intervals, in RAM.
- Time scales: TAI, GPS time, MJD/JD, the leap-second table and its expiry; UT1 − UTC from an operator-placed file only.
- Independent references (optional `noselect` servers): agree or disagree, never a cause.
- NTP service counters from chrony's `serverstats`; a measured NMEA offset recommendation.
- Oscillator log: SoC temperature with chrony's frequency, 10-minute bins appended hourly.

### Security and installation

- Administrative security (GPS-014, GPS-017, GPS-019): Host allowlist, same-origin POST with a bearer admin token, an unprivileged `gps-time` service with systemd hardening and a narrow polkit rule; security headers and CSP.
- Installer: a venv for Python dependencies, a preflight, Debian 12 and 13 (Python 3.11 and 3.13) tested in CI with aarch64 wheels checked.
- Deploy scripts stop on failure and verify the upload's SHA-256; the bundle ships the built web UI.
- Config and survey persistence: SIGTERM flush, atomic writes with fsync, a previous-file checkpoint, corrupt files set aside.

### Web UI (`/app/`)

- The React station UI with self-hosted fonts and no runtime CDN or analytics. All 21 legacy-parity items are ported, decided or dropped; ported are administration, almanac, sky and object lookup, survey, chrony tracking, offset history with its uncertainty band, page configuration and the night theme.
- Local-time clock (display only), sun shifts per day, Earth shadow and satellites from an offline TLE cache, screenshot mode.
- Location privacy honored by the almanac, object lookup, sidereal time, satellite positions and the local-time zone.
- The legacy server-rendered pages are still present in this release. They were removed on main afterwards (#99), for the next release.

## The station it was tested on

A development unit, not a reference installation: Raspberry Pi 4 with an Uputronics MAX-M8Q board. Its weak C/N₀ is an antenna and site limit (owner's assessment): at the check 9 of 23 satellites used, best C/N₀ 25 dB-Hz, median of those used 18 dB-Hz (`observed`). The rc.8 run and rc.10's first hours had real PPS outages on this unit; this run had none. The station observes signal levels and outages; it does not name their cause.

## Known open issues

- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- Accuracy against UTC is not measured: it needs an independent reference this unit doesn't have.
- `SPEC-TIMING-METROLOGY.md` §2 (NTS) and §5 (PTP) are not started.
- 32-bit Raspberry Pi OS (`armv7l`) isn't covered by the wheel check.
- The station serves plain HTTP: use it on a trusted LAN, or put a TLS reverse proxy in front.
- Full list: `docs/STATUS.md`.

## Deploy and rollback

- Station on 1.4 (rc.8 to rc.11): `docs/deploy/upgrade-1.4-station.md`; a station already on rc.11 runs the same code and needs no upgrade. New Pi: `docs/deploy/fresh-pi-install.md`. v1.3 station: `docs/deploy/first-pi-deploy.md`.
- `install.sh` restarts chrony on every run, as it has since v1.3; expect one short PPS NOT USED BY CHRONY event at the start.
- Rollback: `v1.4.0-rc.10` with the same deploy command; details in the upgrade checklist's last section.
