# GPS Time v1.4.0-rc.3

**Date:** 2026-10-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.2](v1.4.0-rc.2.md)

Third release candidate, and the intended bundle for the first Pi deploy of the 1.4 line. It makes the deploy scripts safe to use and adds the sun shift table. **Nothing in the 1.4 line has run on a Pi yet**: not the unprivileged service, the polkit rule, the venv installer or the deploy scripts.

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.2 (#29–#33).

## Deploy scripts stop on failure (#30): GPS-021

- `deploy-to-pi.ps1` checks the exit code of every `python`, `scp` and `ssh` call. Before, a failed build could upload an old archive from `dist/`.
- Both scripts:
  - delete any old archive before building;
  - upload into a fresh `~/gps-time-deploy` on the Pi, not a fixed `/tmp` name;
  - check the archive's SHA-256 on the Pi before running `install.sh`.

## Sun shifts per day (#31)

- `/app/` Sun & Daylight card: sunrise, solar noon, sunset and daylight length vs yesterday and to tomorrow, in signed seconds, labeled predicted. DST clock changes are excluded and noted.
- `/api/almanac` → `neighbors` gains `noon`.
- Legacy dashboard: "change vs yesterday" keeps its minus sign, and a missing value shows "–" instead of 0.

## Repository

- CI lints every workflow file with actionlint, so an invalid workflow fails a check (#29).
- SDR and RF observatory roadmap added; scoping only, not scheduled (#32).

No change to chrony, gpsd or PPS configuration in this release.

## What `install.sh` does to timing on every run

This is unchanged since v1.3, but it matters for a deploy:

- It makes sure `/etc/chrony/chrony.conf` has `log tracking` and `logdir /run/chrony-log`.
- It **restarts chrony**. Expect chrony to take a few minutes to select PPS again; the status shows the fallback source or ACQUIRING until then.

## Known open issues

- Not verified on a Pi: systemd hardening, the polkit rule (needs polkit ≥ 121), `_chrony` socket access, `vcgencmd` under `video`, the venv install, the deploy scripts.
- `web/dist` isn't shipped in the Pi bundle. On a station, `/app/` returns 503 unless the built UI is copied there by hand.
- chrony history semantics (GPS-003, GPS-007); unbounded RAM tracking log (GPS-011, GPS-012).
- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
- Full list: `docs/STATUS.md`.

## Upgrade notes and rollback

Same as [v1.4.0-rc.2](v1.4.0-rc.2.md): deploy from an interactive terminal so the admin token is shown; keep the token; add extra hostnames to `GTP_ALLOWED_HOSTS`.

Rollback has two levels, both in `docs/development/raspberry-pi-deploy.md` → "Rollback":

- **Level 1:** the root-service drop-in, keeping this code.
- **Level 2:** the previous release. For a station still on v1.3, that is the backup of `/opt/gps-time-pi` taken before the deploy.
