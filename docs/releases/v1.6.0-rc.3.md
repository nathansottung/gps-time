# GPS Time v1.6.0-rc.3

**Date:** 2026-11-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.6.0-rc.2](v1.6.0-rc.2.md); last stable [v1.4.0](v1.4.0.md)

rc.2 with nine additions from the owner's list (2026-11-04), one PR each (#156 to #164). Everything in rc.1 and rc.2 is still here: [`v1.6.0-rc.1.md`](v1.6.0-rc.1.md) has what the 1.6 line carries and what the upgrade changes, and [`v1.6.0-rc.2.md`](v1.6.0-rc.2.md) has the bundle fix. v1.5.0 stays skipped. **The formal soak waits for the antenna move**; the first run of a 1.6 candidate is for sector data and web SDR testing.

**All nine are opt-in or off until used.** None changes chrony, gpsd or the PPS setup on the station. The one chrony change is on an SDR node, at the owner's request: a second Pi's chrony follows the station.

## What's new

| # | What | How it's turned on | Guide |
|---|---|---|---|
| #156 | **The deploy scripts pass `install.sh`'s flags.** `$env:GTP_WEBSDR = '1'` (and the others) go through to `sudo env … bash install.sh`. | #157 | **The station's own DVB-T driver blacklist**, so the TV driver can't hold the RTL-SDRs. Written by the SDR stack and the web SDR installers, with the driver unloaded at once. | `GTP_SDR=1` or `GTP_WEBSDR=1` | `deploy/sdr-stack.md` |
| #158 | **The web SDR's WebSockets through the password gate:** a CI test against a fake OpenWebRX+, and `python -m gps_time_pi.websdr_gate check http://<station>:8073/` for a check from your PC. | — | `deploy/websdr.md` → "Check it from your PC" |
| #159 | **Dongle roles by serial across both installers, at most 3 on a Pi 4** (owner's limit). Refused before anything changes; shown on Administration → SDR receivers. | — | `deploy/sdr-stack.md` → "Roles and the limit" |
| #160 | **Migration:** config and survey, station key, admin token hash, web SDR password and oscillator log, in one AES-256-GCM file with a passphrase. Never the event history, evidence or sky map. | `python -m gps_time_pi.migrate export\|import` | `deploy/migrate.md` |
| #161 | **Opt-in ADS-B feeders:** Beast to adsb.fi, airplanes.live, ADSBExchange or one of your own, and FlightAware's PiAware (repository key pinned, never reads gpsd). Each is off until turned on in Administration with its name typed. MLAT is a separate opt-in, refused in hidden mode. A **Location sharing** card lists everything that shares the station's location. | `GTP_FEEDERS=1` (+ `GTP_FEEDERS_PIAWARE=1`) | `deploy/feeders.md` |
| #162 | **FAA airband bookmarks** for the web SDR: built-ins, plus the NASR set within 80 km. Each set carries its 28-day cycle date and is flagged once past it. **Refresh now** on the Radio page; none in hidden mode. | with `GTP_WEBSDR=1` | `deploy/websdr.md` → "Airband bookmarks" |
| #163 | **SDR node mode:** a second Pi with the dongles, web SDR and feeders. Its chrony follows the station, so its timestamps are labelled `ntp`, and its feeds serve the station's address only. The station reads the node's aircraft and links to its web SDR. | on the node `GTP_NODE=1 GTP_NODE_STATION=…`; on the station `GTP_SDR_NODE=…` | `deploy/sdr-node.md` |
| #164 | **Clip recording:** audio (AM, NFM, wide FM) and IQ, as signed SigMF with the station's timing (time source, chrony's bound, USB-buffer uncertainty). New routes: `/api/feeders`, `/api/airband`, `/api/time-quality`, `/api/clips` (+ `/api/clips/file`). New admin action: `refresh_airband`. New `POST /api/setting` keys: `feeder`, `clip`, `clip_delete`. The reference is `api/endpoints.md`.

## What the upgrade changes on the station

Without any new flag, these are all that changes:
- **The polkit rule** also allows the web service to start or stop exactly these units, and nothing else new:
  - start `gps-time-clip.service` and `gps-time-airband-fetch.service`;
  - start, stop and try-restart `gps-time-feed@<name>.service` and `piaware.service`.
- **The clip recorder** (`gps-time-clip.service`, a one-shot, never enabled) and its RAM folder `/run/gps-time-clips` (tmpfiles.d).
- `/etc/default/gps-time-clips`, written with the defaults (RAM, 64 MB).

The rest comes only with its flag (the table above).

## Deploy

From a clean working tree on Windows, in a normal PowerShell window:

```powershell
git fetch --tags
git checkout v1.6.0-rc.3
git describe --tags --dirty          # must print exactly v1.6.0-rc.3
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

With options for this run, which is not the formal soak, set them first in the same window. For example, the web SDR on the 1090 MHz dongle: `$env:GTP_WEBSDR = '1'`. Remove them afterwards (`Remove-Item env:GTP_WEBSDR`) so a later deploy doesn't pass them again.

## Not yet verified on a Pi

None of the nine has run on a Pi. Each guide has its own "Not verified" section. The main ones:
- the PiAware install on trixie arm64;
- Debian readsb's feeder options;
- the FAA file's column names (their server answered this machine with 503);
- the node's chrony and LAN allow-lists on two Pis;
- the clip demodulators and the USB-buffer figure on a real dongle;
- migration between two real cards.

## Rollback

Check out `v1.6.0-rc.2` (or `v1.5.0-rc.1`, `v1.4.0`) and run the same deploy command. Before that, run whichever of these you used: `GTP_FEEDERS=0`, `GTP_NODE=0` / `GTP_SDR_NODE=none`, `GTP_WEBSDR=0`, `GTP_SDR=0`.
