# GPS Time v1.4.0-rc.6

**Date:** 2026-10-04 · **Type:** pre-release (release candidate) · **Previous:** [v1.4.0-rc.5](v1.4.0-rc.5.md)

Sixth release candidate, and the bundle the two deploy checklists target. It fixes the Windows deploy script, which failed at the install step on its first real run.

Source: `docs/provenance/change-log.md`, entries after v1.4.0-rc.5 (#40, #41).

## deploy-to-pi.ps1: ssh `-t` was joined to user@host (#40)

- From an interactive terminal, the install step failed with ssh's `Bad configuration option: ...`. The build, the first ssh call and the upload succeeded; `install.sh` never ran, so the Pi was left with only an uploaded archive in `~/gps-time-deploy`. Running the deploy again replaces it.
- Cause: PowerShell turned the one-element option list into a string and joined it to the next argument, so ssh received `-tuser@host ...` as one argument.
- The argument list is now built element by element. New tests assert the exact ssh argv for both deploy scripts, with and without `-t`.
- `GTP_DEPLOY_TTY=1` or `0` overrides the terminal detection in both scripts.

The station software is unchanged from rc.5.

## First contact with a Pi

The deploy script has now run against a Pi as far as the upload. Everything after that is still unverified on a Pi: `install.sh` and its preflight, the venv, the unprivileged service, the polkit rule, the web UI install.

## Known open issues

- The almanac with the real JPL ephemeris hasn't been run on Python 3.13 with numpy 2.5; the fresh-install checklist checks it on the station.
- A 32-bit Raspberry Pi OS (`armv7l`) isn't covered by the wheel check.
- chrony history semantics (GPS-003, GPS-007); unbounded RAM tracking log (GPS-011, GPS-012).
- GPS-020 remainder: hash-pinned requirements, ephemeris trust-on-first-use, staged install.
