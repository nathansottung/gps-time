## What the upgrade changes on the station

Without any new flag, these are all that changes:
- **`/opt/gps-time-pi/holdover-scorecard.json`**, next to `timing-events.json`. It is written once per outage when it closes, capped at 200 entries, with no position. Each outage also adds one checkpoint write to keep its prediction. Nothing is written at 1 Hz.
- The feeder cards' wording (#166, #167). Nothing the feeders send has changed.

## Deploy

From a clean working tree on Windows, in a normal PowerShell window:

```powershell
git fetch --tags
git checkout v1.6.0-rc.4
git describe --tags --dirty          # must print exactly v1.6.0-rc.4
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-to-pi.ps1 -PiHost $PiHost -PiUser $PiUser
git checkout main
```

**With the web SDR**, set its flags in the same window before the deploy command:

```powershell
$env:GTP_WEBSDR = '1'                 # install the web SDR (OpenWebRX+ behind the password gate)
$env:GTP_WEBSDR_SERIAL = '00001090'   # only if the SDR stack has no 1090 MHz serial set: the dongle's serial
$env:GTP_WEBSDR_PORT = '8073'         # optional: the LAN port (1024–65535, not 8074; default 8073)
$env:GTP_WEBSDR_MAX_HOURS = '4'       # optional: a session ends by itself after this many hours (1–24)
```

The password is set on the Pi afterwards (`deploy/websdr.md`). Remove the flags after the deploy (`Remove-Item env:GTP_WEBSDR, env:GTP_WEBSDR_SERIAL, env:GTP_WEBSDR_PORT, env:GTP_WEBSDR_MAX_HOURS -ErrorAction SilentlyContinue`) so a later deploy doesn't pass them again. The settings are kept on the Pi in `/etc/default/gps-time-websdr`.

## Not yet verified on a Pi

- **The holdover scorecard** hasn't seen a real outage. The tests drive whole outages on fixtures, but the first real entry will be the first check of the measurement point: the first pulse with pulses and GNSS both good again.
- Everything listed in [`v1.6.0-rc.3.md`](v1.6.0-rc.3.md) → "Not yet verified on a Pi" still applies.

## Rollback

Check out `v1.6.0-rc.3` (or `v1.6.0-rc.2`, `v1.4.0`) and run the same deploy command. `holdover-scorecard.json` is left in place and ignored by older versions. Before that, run whichever of these you used: `GTP_FEEDERS=0`, `GTP_NODE=0` / `GTP_SDR_NODE=none`, `GTP_WEBSDR=0`, `GTP_SDR=0`.
