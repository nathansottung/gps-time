# Desktop UI review of the v1.5.1 candidate, 2026-10-27

The third item before v1.5.1-rc.1 (`docs/releases/v1.5.1-plan.md`): a review of `main` as it would become the candidate (after #142 and #143), in the desktop demo. Bugs only, no new features.

## How it was checked

**Against the station's own server.** The UI was built and served by the Python demo station (`gps_time_pi.server` with `GTP_DEMO=1`), with the station's demo API. That differs from the browser tests (`e2e/`), which use the client-side demo adapter: a different code path with different data.

**New opt-in check:** `web/e2e-station/station.spec.ts`, run with `corepack pnpm run test:station` (`playwright.station.config.ts`). It is read only. Point it at a station with `GTP_STATION_URL`; the default is the desktop demo on port 8080. It covers every page and tab:
- the layout audit at 360, 768, 1280 and 1920 px;
- the design audit (contrast, type scale, weights, figures) at 1280 px;
- no console errors;
- in screenshot mode, the demo position (the US Naval Observatory) never appears on screen;
- the red night theme's layout.

**By eye:** full-height screenshots at 360 and 1280 px of every page and tab, the night theme's Overview and Timing, and spot checks in a browser at 360 px.

**Result:** 72 of 72 checks pass with one browser at a time.

## Found and fixed

| # | Where | Found | Fix |
|---|---|---|---|
| 1 | Timing → Overview, PPS state availability (a planned preview, demo only) | The hour labels (00:00 … 24:00) were drawn stretched wide and squashed: SVG text inside a graphic stretched with `preserveAspectRatio="none"`. The layout audit can't see this | The bar stays a stretched SVG; the labels are HTML below it |
| 2 | Timing → Overview, Holdover performance | The x-axis was a category axis: outages in list order (1387 s, 161 s, 58 s…), and at 360 px only 2 of 5 points were drawn | A numeric, logarithmic duration axis (10 s, 100 s, 16m 40s…); all points at every width; dot size restored |
| 3 | Timing, Holdover projection table | At 360 px "±1 µs" and the times broke across lines | No line breaks inside a value |
| 4 | Timing → Oscillator, Temperature and frequency over time | The date ticks repeated ("Oct 26" twice) | One tick per local midnight, fewer on long spans (`dayTicks`, tested) |
| 5 | Administration → Admin access | "Everything the legacy /admin page does is now on this page", with a link to a page removed in v1.5.0 | Sentence removed |
| 6 | Night theme tooltip; Configure | "Shared with the legacy pages" | Now "remembered in this browser" |

## Found, not changed (for the owner)

- **Night theme legibility.** In the red night overlay, values coloured green or cyan ("HEALTHY", "SELECTED", the large remaining-correction figure, some status badges) are hard to read: the overlay keeps only the red channel. The 2026-10-26 design review left the night theme's values alone on purpose ("a different question"). Changing them is a design decision.
- **The station's HTTP server accepts few connections at once.** `ThreadingHTTPServer` keeps Python's default listen queue of 5.
  - **Seen:** with three to eight browsers loading pages at the same moment, some requests were refused (`ERR_CONNECTION_REFUSED`), and the page showed those values as not answered. With one browser, nothing was refused.
  - **Why not changed here:** it relates to review finding GPS-018 (per-request fan-out, no limits), and it is a server change, not a UI one. So it isn't in this UI pass.
- **Planned previews** (Timing's availability, outage statistics, recovery; other `<Planned>` cards) show synthetic numbers in demo mode, as designed, and "not available" on a station.

## Not covered

- These are the "Checks on the Pi after the owner deploys rc.1" in the v1.5.1 plan.
